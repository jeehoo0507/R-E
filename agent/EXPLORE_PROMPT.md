# 하루 자유 탐색 프롬프트 (서버 에이전트용)

아래 내용을 서버의 Claude Code 첫 메시지로 그대로 붙여 넣는다. 저장소 루트에서 실행한다.

---

너는 이 저장소(`decap_loop`)에서 **24시간 동안 자유롭게 탐색하는 연구 에이전트**다. 목적은 하나다.

> **"판을 공진(모드) 정보로 보는 멀티 토큰 정책이, 좌표·고정 주파수 입력 정책보다 학습한 판보다 크고·모양이 다르고·종류가 다른 판에서 더 잘 버티는가?"** 이 질문에 답하는 데 가장 유용한 사실을 24시간 안에 최대한 많이, 재현 가능하게 찾아라.

## 먼저 읽을 것 (순서대로, 30분 이내)
1. `README.md`
2. `reports/방향 확정.md` — 범위와 사다리(0~3단) 구조
3. `reports/최종 모델 설계.md` §3 — 모드/포트/decap 토큰 설계
4. `research_notes/토큰 데이터 분석/결과.md` — 학습 없는 분석 결과 (무엇이 전이되고 무엇이 뒤집히는지)
5. `sanity_check.py`, `train.py`, `decap_loop/model.py`, `decap_loop/verify.py`

## 자유롭게 해도 되는 것
- 사다리 어느 단이든 먼저 시도해도 된다 (0단 좌표 / 1단 공진 포트 특징 / 2단 모드 토큰 + cross-attention / 3단 루프).
- 새 특징, 새 정규화, 새 토큰 구성, 새 모델 파일을 **새 파일**로 만들어 시험해도 된다.
- 작은 판, 짧은 학습(수백 iter), 시드 1개로 **빠르게 많이** 돌려라. 하루의 목적은 최종 숫자가 아니라 **"무엇이 효과가 있고 무엇이 아닌지"의 순위**다.
- 학습 없이 답할 수 있으면 학습하지 마라 (`research_notes/토큰 데이터 분석/`의 방식처럼).

## 반드시 지킬 것
1. **환경 파일 수정 금지:** `decap_loop/pdn.py`, `sim.py`, `verify.py`, `bank.py`. 필요하면 새 파일로 감싸라.
2. **성공 판정은 `verify.py`의 700점 정확 검사로만.** 32점 격자 결과를 성공률로 보고하지 마라.
3. 모든 실행은 `runs/explore/<이름>/`에 `config.json`(인자·seed·git hash), `log.txt`, `metrics.json`을 남긴다. 숫자는 로그에서만 가져온다. **추정·예시 숫자를 쓰지 마라.**
4. 학습 1회 ≤ 2시간. 2시간 넘으면 중단하고 그 시점 결과를 기록한다.
5. 같은 비교 안에서는 **한 번에 하나만** 바꿔라 (모델 크기, 학습 iter, 데이터는 고정).
6. 다른 세션이 환경 파일을 고치고 있을 수 있다. 시작 때와 종료 때 `git status`를 기록하라.
7. 막히면 30분 이상 한 문제에 매달리지 말고 기록하고 다음으로 넘어가라.

## 24시간 뒤 제출물: `runs/explore/REPORT.md`
아래 형식으로. 20줄짜리 요약을 맨 위에.

```
## 요약 (10줄 이내)
- 가장 확실한 발견 3개 (각각 숫자 + 로그 경로)
- 효과 없었던 것 3개
- 사다리 어느 단까지 동작 확인했나

## 결과표
| 실험 | 입력/모델 | 학습 판 | 평가 세트 | 성공률(700점) | 개수/greedy+prune | 시간 | 로그 |

## 발견한 문제 (버그, 불안정, 메모리 등)

## 다음 날 추천 큐 (우선순위 5개, 각 1줄, 이유 포함)

## 하지 말아야 할 것 (오늘 해보고 안 된 방향)
```

## 성공의 기준
"잘 됐다"는 결과를 가져오는 것이 아니다. **안 되는 것을 안 된다고, 되는 것을 숫자와 로그로** 가져오면 성공이다. 좋은 결과를 만들려고 설정을 비트는 것이 가장 나쁜 결과다.
