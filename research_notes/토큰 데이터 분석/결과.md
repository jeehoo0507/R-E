# 토큰 후보 학습 없는 분석 결과 (2026-10-22)

스크립트: `token_analysis.py`, 로그: `run_15x10.log`
설정: 10×10칸, 종류마다 판 15개 (rect/L/holes), probe 1개, 목표는 평탄형 (모든 포트에 한 종류를 채운 해의 최악값 × 1.5~3, 해가 있음을 보장)
- PCB형: 기본 `PDNConfig`, 검사 대역 10 MHz~5 GHz, decap 10 nF / 1 nF / 100 pF
- 인터포저형: 셀 200 µm, 유전체 1 µm, decap 100 pF / 20 pF / 5 pF, 검사 대역 200 MHz~20 GHz
- 선생님 = 정확한 1수 greedy + prune. 성공 판정은 700점 정확 검사

## A4 특징 하나로 만든 규칙 배치 (prune 후 개수 / greedy+prune 개수, 중앙값, 성공률 모두 100%)
| 규칙 | PCB | 인터포저형 |
|---|---|---|
| greedy (정확한 1수) | 1.00 | 1.00 |
| 좌표 (probe에 가까운 순) | 1.00 | 1.44 |
| loop L 작은 순 | 1.00 | 1.38 |
| 고정 8점 최악 주파수 | 1.12 | 1.15 |
| 모달 (최악 모드 결합도) | 1.00 | 1.15 |

## 해석
1. **좌표와 주파수 한 점의 loop L은 종류를 넘으면 방향이 뒤집힌다** (AUC 0.82→0.42, 0.79→0.35). PCB에서는 "probe에 가깝고 인덕턴스가 작은 자리"가 좋지만 인터포저형에서는 아니다. 규칙 배치도 인터포저형에서 1.4배 더 쓴다. → Park식·Manoharan식 표현의 한계를 데이터로 보여준다.
2. **정확한 1수 효과가 가장 잘 옮겨간다** (0.84→0.92). 계산기가 이미 싸게 주는 값이므로 (포트, decap) 쌍의 특징으로 넣는다. 단, 선생님이 greedy(같은 값으로 고른다)라서 이 AUC는 부풀려져 있다.
3. **모달 결합도는 PCB에서 좋고 인터포저형에서 약해진다** (0.82→0.57). 뒤집히지는 않지만 기대만큼 옮겨가지 않는다. 분포도 크게 다르다 (KS 0.96). 정규화를 다시 설계해야 한다.
4. 모드 특징(f/f_c, Q, \|Z\|/Zt)은 두 종류에서 분포가 완전히 갈린다. 현재 정규화로는 "종류를 지운다"는 주장을 할 수 없다.

## 한계
- 10×10 판에서는 대역 안 모드가 판당 1개뿐이라 모달 표현을 시험하기에 약하다 → 20×20 이상 필요
- 선생님이 greedy라 1수 효과 특징에 유리하다 → LS 선생님으로 다시 확인 필요
- 판 15개씩, 신뢰구간 없음, 시뮬레이터 상수는 임시값
- 특징 하나씩만 본다. 상호작용(반공진)은 학습 실험에서 확인해야 한다

# v2: 20×20 판, LS 선생님, 모달 정규화 점검, 특징 묶음 (2026-10-22)

스크립트: `token_analysis2.py` (로그 `run2_10x20.log`), `token_combo.py` (로그 `combo_10x20.log`, 캐시 `combo_cache_10x20.pkl`)
설정: 20×20칸, 종류마다 판 10개, 주파수 350점. 선생님 = greedy+prune 후 LS (2개 빼고 greedy로 메우기, 40회)
- LS / greedy+prune 개수: PCB 중앙값 0.81 (70% 판에서 개선), 인터포저형 1.00 (10%만 개선) → 인터포저형 라벨은 사실상 greedy 해

| 특징 | KS | AUC PCB → IP |
|---|---|---|
| 좌표 | 0.12 | 0.77 → 0.46 |
| loop L (Manoharan) | 0.66 | 0.70 → 0.43 |
| 고정 8점 \|Z_pi\| | 0.61 | 0.58 → **0.06 (뒤집힘)** |

## 모드 정규화 (PCB vs IP KS)
주파수 원값 1.00 → f/대역 중심 0.62, 대역 안 상대 위치 0.62, f/SRF 중간값 0.70, SRF 범위 안 위치 1.00. Q 1.00, |Z|/Zt 1.00.
→ 대역 기준 정규화가 가장 낫지만 여전히 다르다. Q와 목표 대비 크기는 완전히 갈린다.

## 특징 묶음 (로지스틱 회귀, 판별 AUC 평균)
| 묶음 | PCB→PCB | IP→IP | PCB→IP | IP→PCB |
|---|---|---|---|---|
| 좌표 | 0.74 | 0.48 | 0.46 | 0.23 |
| loop L | 0.68 | 0.53 | 0.43 | 0.30 |
| 고정 8점 | 0.81 | 0.77 | 0.46 | 0.69 |
| loop L + 고정 8점 (Manoharan 전체) | 0.88 | 0.86 | 0.45 | 0.59 |
| 정확한 1수 효과 | 0.73 | 0.98 | **0.98** | **0.74** |
| 공진만 | 0.86 | 0.88 | 0.59 | 0.32 |
| 공진 + 1수 | 0.87 | 0.89 | 0.64 | 0.31 |
| **공진 + 1수 + 고정 8점** | **0.93** | **0.95** | 0.55 | 0.46 |
| 전부 | 0.92 | 0.95 | 0.56 | 0.45 |

## 결론
1. **같은 종류 안에서는 공진 + 여러 토큰이 가장 좋다** (0.93 / 0.95). 특히 PCB에서 1수 효과만으로는 LS 선생님의 판단을 못 잡지만 (0.73), 공진 정보를 더하면 잡는다 (0.93). → 공진 정보가 "여러 수에 걸친 판단"을 담고 있다는 근거.
2. **종류를 넘으면 지금 정규화의 공진 특징은 거의 무작위다** (PCB→IP 0.55~0.64, IP→PCB 0.31~0.46). 특징을 더할수록 원래 종류에 과적합된다.
3. **종류를 넘어 버티는 건 정확한 1수 효과뿐이다** (0.98 / 0.74). 단, 인터포저형 라벨이 사실상 greedy 해라서 PCB→IP 0.98은 부풀려져 있다.
4. 모달 특징 중 **참여비 log(r_ii/r_pp)만 단독으로 잘 옮겨간다** (0.56→0.87). 결합도 g, r_pi 상대값, 감쇠력은 뒤집히거나 무너진다.

## 설계에 반영할 점
- 정확한 1수 효과를 (포트, decap) 쌍 특징으로 꼭 넣는다
- 모달 특징은 무차원 상대량(참여비, 대역 안 상대 위치)만 남기고, Q·|Z|/Zt·감쇠력처럼 절대 크기에 묶인 값은 빼거나 다시 정규화한다
- "PCB만으로 학습 → 칩 zero-shot"보다 **여러 종류를 섞어 학습**하는 쪽이 현실적이다
- 이 결과는 선형 모델 기준이다. 트랜스포머가 다르게 조합할 수는 있지만, 지금 정규화로 종류를 넘는다는 주장은 근거가 없다
