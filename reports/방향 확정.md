## 2. 확정 범위: 주장 하나

> **"decap 배치 정책이 학습한 판보다 크고 모양이 다른 판에서도 통하려면, 판을 좌표가 아니라 전기적 특징(공진 참여도 + 정확한 1수 효과)으로 봐야 한다."**

이 주장은 **결과가 어느 쪽이든 보고서가 된다.**
- 전기 특징이 이기면: "표현이 일반화를 만든다"
- 비기면: "작은 판에서는 표현 차이가 없고, greedy+prune이 충분하다" + 선생님 분석 결과
- 둘 다 greedy+prune에 지면: "학습 없는 분석에서 공진 정보가 선생님 판단을 담는다(0.93)는 것은 확인했지만, 학습으로 옮기지 못했다" + 원인 분석

### 포함 / 제외

| 포함 ✅ | 제외 ❌ (고찰의 향후 과제로 한 문단) |
|---|---|
| 같은 정책 구조 + 입력만 3가지: 좌표 / 고정 주파수 Z / 공진 참여도 + 1수 효과 | 루프 트랜스포머 (근거 없음, 불안정) |
| 일반화 축: **크기** (8~12칸 → 20, 30칸), **모양** (rect/L/holes → U, 고리) | 판 **종류** 넘기 (이미 "지금 방식으로는 안 됨" 확인. 분석 결과만 고찰에 인용) |
| 기준선: greedy+prune, LS | GA, Manoharan 재현 (고정 주파수 입력이 Manoharan식 대체) |
| 학습 없는 분석 2개 (이미 완료): 가짜 성공 1.00→0.00, 특징 전이 분석 | GRPO·clipping 등 학습법 변형 (기본 REINFORCE+그룹 기준선만) |
| 시드 3개, 700점 정확 검사 | 실제 HBM 데이터, 수천 포트 |

### 모델: 새로 만들지 않는다
- 기존 `decap_loop/model.py`의 정책(`--feat phys` / `--feat coord`)에 **`--feat modal` 채널만 추가**한다.
- modal 채널 = 포트별 (공진 참여비 log(r_ii/r_pp), 최악 공진 결합도, 잔여 L, 정확한 1수 효과). 데이터 분석에서 같은 종류 안 AUC 0.93을 낸 묶음 그대로.
- 모드↔포트 cross-attention, decap 토큰, O(N·K) 구조는 **만들지 않는다.** 포트 특징으로 충분하다는 것이 분석 결과다.

## 5. 서버 에이전트 운영 방식 ("쓸데없이 난해해지는 것"을 막는 장치)

에이전트에게 **자유 탐구를 시키지 않는다.** 사전 등록된 실험 목록을 순서대로 실행하고 결과를 기록하는 **실험 집행자**로만 쓴다. 방향 결정은 사람이 아침마다 한다.

### 5.1 구조
```
서버: tmux 세션 1개 + Claude Code 1개
  ├ EXPERIMENTS.md   ← 사전 등록 실험 큐 (사람만 수정)
  ├ RULES.md (CLAUDE.md) ← 에이전트 행동 규칙
  ├ runs/            ← 실행마다 config.json + log + metrics.json
  ├ RESULTS.md       ← 로그에서 자동 생성되는 결과표 (에이전트가 갱신)
  └ PROPOSALS.md     ← 에이전트가 "해보고 싶은 것"을 적는 곳 (실행 금지, 사람 승인 후 큐로 이동)
```

### 5.2 에이전트 규칙 (RULES.md에 그대로 넣기)
1. `EXPERIMENTS.md`의 큐에 있는 실험만 실행한다. 큐에 없는 실험을 돌리지 않는다.
2. 새 모델 구조, 새 손실 함수, 새 특징을 만들지 않는다. 아이디어는 `PROPOSALS.md`에 3줄 이내로 적고 멈춘다.
3. 모든 실행은 seed, config 해시, git commit을 기록하고 **700점 정확 검사**로 평가한다. 32점 검사 결과는 보고하지 않는다.
4. 실행이 끝나면 `RESULTS.md`의 표 한 줄을 로그에서 **스크립트로** 생성한다. 손으로 숫자를 적지 않는다.
5. 실험이 실패(발산, NaN, 시간 초과)하면 같은 설정으로 **1회만** 재시도하고, 그래도 실패하면 "실패"로 기록하고 다음 큐로 넘어간다. 원인 분석은 하되 코드를 고치지 않는다.
6. 하루 끝에 `DAILY.md`에 **10줄 이내** 요약: 끝난 실험, 숫자, 실패, 내일 큐. 해석이나 제안은 쓰지 않는다.
7. `decap_loop/pdn.py`, `sim.py`, `verify.py`(환경)는 수정 금지. 수정이 필요하면 PROPOSALS.md에 적는다.
8. 11/8 이후에는 어떤 실험도 시작하지 않는다.

### 5.3 사람의 하루 루틴 (10분)
- 아침: `DAILY.md`와 `RESULTS.md` 읽기 → 큐 순서 조정 또는 PROPOSALS 승인/거절 → 큐 확정
- 그 외 시간은 보고서 작성에 쓴다
