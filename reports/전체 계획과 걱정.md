### 3일 동안 하는 것 / 버리는 것 (최소판 이전 버전)
| 하는 것 | 버리는 것 (나중에) |
|---|---|
| H0 결과를 반영한 촘촘한 검사 환경 | R0~R2 팔, M−* ablation |
| 모달 특징 (`--feat modal`): AAA pole + residue 적합 | 계산기 검산 루프(H4), ACT |
| MoTT 모델: 모드↔포트↔decap attention, **블록 1개를 공유해 R ~ U{2..8} 반복** (루프가 기본) | 고정 깊이 대조 (시간 남으면) |
| 대조군 R4: 같은 모델, 모드 토큰 대신 고정 주파수 토큰 | GA, PAGA, Manoharan 재현 |
| 기준선: greedy+prune, LS | 시드 3개 → **시드 1~2개** |
| zero-shot 평가: 크기(16·20·30칸), 인터포저형 파라미터, 새 라이브러리, 테스트 때 R 2→16 | 실제 HBM 공개 데이터 (가능하면 3일차에 시도) |

### 일정
| 날 | 오전 | 오후~밤 (서버가 도는 동안) |
|---|---|---|
| **1일차** | H0 확정(다른 세션 결과 반영). `modal_features.py`(새 파일), `mott.py`(새 파일) 구현, 작은 판 sanity 테스트 | 평가 세트 고정 + greedy+prune·LS 기준선 실행 (CPU) |
| **2일차** | 학습 짧게 돌려서 iter당 시간 측정 → 반복 수 결정 | **M과 R4를 동시에 학습** (각 8~12시간, PCB 8~12칸) |
| **3일차** | zero-shot 평가 + 테스트 때 R 변화 (추가 학습 불필요) | 표 2개, 그림 1개 작성. 결과에 맞춰 주장 범위 정하기 |

### 3일 뒤에 말할 수 있는 것
- M이 R4보다 크기·기술 변화에서 낫다 → "모드 표현의 예비 증거" (시드 1~2개라 **예비**로 표기)
- 테스트 때 R을 늘리면 모드가 많은 판에서 좋아진다 → "루프 효과의 예비 증거"
- 둘 다 아니다 → "32점 검사의 가짜 성공(1.00 → 0.00)" + 기준선 표가 결과물

### 3일 안에 생길 위험
1. 촘촘한 격자 때문에 iter가 너무 느림 → 판 크기를 8~10칸으로 줄이고, 주파수 128점 + 피크 근처 추가점으로 타협
2. AAA pole 추출이 학습 중에 터짐 → 실패하면 피크 검출 pole로 대체하고, K ≤ (M−2)/2로 제한
3. RL이 2일차 안에 수렴하지 않음 → 모방(LS 선생님) 비중을 크게 해서 사실상 모방 학습으로 결과를 냄
4. 서버 CPU 코어가 적음 → 두 팔을 순서대로 돌리고 각 6시간으로 줄임

## 0. 한 줄 요약

> 느린 선생님(LS·GA)의 판단력을, 매 단계 **공진 모드 토큰**을 보는 **루프 트랜스포머** 정책에 증류하고, 한 수씩 두며 강화학습으로 선생님을 넘어서게 한다. 한 수의 물리는 Woodbury 공식이 정확히 계산하고, 여러 수에 걸친 판 전체의 결과는 정책이 암묵적으로 배운다. 목표는 **큰 판**과 **다른 종류의 판**에서도 재학습 없이 동작하는 것이다.

## 1. 새로 확인된 사실 (`최종 모델 설계.md` 이후)

### 1.1 Manoharan TSIPI 2026 전문 (박사논문 Paper I, Scholars' Mine 3459, 6~44쪽)
| 항목 | 내용 |
|---|---|
| 포트 특징 | 주파수 **한 점 f0**에서 잰 loop inductance 스칼라 + 패드 크기 one-hot |
| 포트 순서 | greedy loop-L 순위로 **고정**. 정책은 그 순서대로 각 포트에 **어떤 decap을 놓을지만** 고름 |
| 상태 | ΔZ = Z_IC − Z_target, n_f개 주파수 점 벡터 → MLP |
| 갱신 | 매 단계 Schur 보수로 **전체 Z 행렬** 갱신 (식 6) |
| 학습 | REINFORCE + critic + replay buffer, 랜덤 PCB 25~75포트, Murata 1000종, 50k 에피소드, RTX 4090 24시간 |
| 시험 | 처음 보는 PCB·라이브러리, 10/50/150포트. GA v3와 비슷하거나 더 적은 개수, 시간은 수백~수천 배 빠름 |
| **다른 종류 데이터** | DevFormer(probe 1, 포트 100)와 Park(probe 4, 포트 100) 데이터셋에서 **재학습 없이 목표 만족** (4.2절). 단, 사례 2개이고, 예산을 맞춘 비교이며, 목표가 0.5 Ω로 느슨함 |

→ `최종 모델 설계.md` ★절의 "학습 기반 decap의 일반화는 모두 한 기술 안에서만"은 **정정이 필요하다.** "체계적인 기술 간 평가는 없다"로 바꾼다.

### 1.2 기타 정정
- Neural Modal Decomposition: arXiv 페이지에 학회 표시가 없다 (physics.comp-ph). "NeurIPS 2026 포스터"는 출처를 확인한 뒤에만 쓴다.
- Park 2022: Z를 단계마다 다시 계산하지 않는다 (확인됨, 설계 문서와 일치).
- 공정 비교 (`fair_check.py`): M ≥ 16에서 모달 쪽이 순위 상관이 더 안정적이다. top-1 regret은 섞여 있다 (설계 문서와 일치).

### 1.3 노벨티 (갱신)
> **공진 모드별 포트 참여 정보를 상태로 써서 자리와 종류를 함께 학습으로 고르고, 칩~PCB에 걸쳐 체계적으로 일반화를 검증한다.**

Manoharan과의 차이: 단일 주파수 인덕턴스 → 모드별 참여도, 고정 포트 순서 → 학습된 자리 선택, remove 행동, 전체 Z(O(N²F)) → 열 + 대각(O(N·F)), 시연 2건 → 체계적 평가.

주관적 점수: 노벨티 4~5/10 (Manoharan 전문을 읽은 뒤 하향).

## 2. 최종 구조

### 2.1 토큰 3종 + 엣지 (세부는 설계 문서 §3)
| 토큰 | 개수 | 왜 따로인가 |
|---|---|---|
| 모드 | K (판·기술마다 다름) | 기술이 바뀌면 바뀌는 것이 K와 모드 밀집도 |
| 포트 | N (보드마다 다름) | 크기 일반화 |
| decap | T (라이브러리마다 다름) | 라이브러리 일반화 |

판단 기준: **판마다 개수가 달라지는 것은 각자 따로 토큰 집합으로 만든다.** 포트끼리는 attention하지 않고 모드를 거친다 → O(N·K).

### 2.2 루프 (두 개)
| | 바깥 루프 | 안쪽 루프 |
|---|---|---|
| 하는 일 | decap 하나 놓기 → Woodbury 갱신 → 모드 재추출 | 한 수 두기 전에 같은 블록을 R번 반복 |
| 판이 바뀌나 | 바뀜 | 안 바뀜 (검산 루프 변형에서는 초안을 정확히 평가) |
| 선례 | Manoharan 등 | Universal Transformer, Looped 계열, 개선형 NCO |

**안쪽 루프는 "계산기 검산 루프" 변형을 기본으로 한다** (설계 문서 §3 선택 모듈). 순수 루프는 반복 중에 물리 정보를 새로 얻지 못하므로, "머릿속으로 미래를 굴린다"는 주장을 뒷받침하지 못한다. 검산 루프는 반복마다 상위 m개 초안을 Woodbury로 평가하고 모드 토큰을 교체한다.

### 2.3 학습
1. **모방**: greedy+prune → LS 해 (`train.py --imit --teacher`)
2. **강화학습**: 같은 판을 G=8번 풀어 그룹 평균을 기준으로 삼는다 (POMO 방식 = GRPO의 단순형). 불안정하면 GRPO로 바꾼다 (clipping, 모방 모델 기준 KL, std 정규화 + ε, std≈0인 그룹은 제외)
3. **자기 개선**: 샘플 중 선생님보다 좋은 해는 새 선생님이 된다
4. **보상**: −개수/N_ref − λ·(실패 + 위반), N_ref = greedy+prune 개수, λ는 라그랑주 방식 (실패율 목표 2%)
5. **루프 학습**: R ~ U{2..8} 랜덤. 앞쪽 반복은 기울기 없이, 마지막 k번만 역전파 (Bansal 2022). 매 반복 원래 토큰을 재주입 (recall). ACT/halting은 2단계 옵션
6. 두 "횟수"를 구분한다: **decap 개수는 보상으로 줄이고**, **생각 반복 R은 보상과 무관**하다

## 3. 전체 계획 (단계별 진행·중단 판정)

| 단계 | 할 일 | 기간 | 통과 기준 | 실패하면 |
|---|---|---|---|---|
| **0. 검사 고치기** | 32점 검사 → 적응형 격자 + 최종 700점 재검사 (H0) | 1주 | 99% 해에서 차이 < 5% | 환경부터 다시. 다른 실험 중단 |
| **1. 기준선 표** | 모든 세트에서 greedy, greedy+prune, LS, GA, PAGA, 모달 휴리스틱, **Manoharan 재현**(loop-L 순서 + ΔZ MLP) 실행 | 1주 | — | 이 표 자체가 1단계 기여 |
| **2. 표현 판정 (핵심)** | MoTT vs R4(고정 주파수 토큰), **루프 없이** 고정 깊이, 3시드 (H1) | 2주 | 설계 문서 H1 기준 | 모달 우위 주장 폐기 |
| **3. 실제 다른 구조 데이터** | 공개 데이터(RL4CO/DevFormer DPP, Park HBM)로 기술 간 zero-shot. Manoharan과 같은 무대 | 1~2주 | PCB로 학습한 MoTT가 Manoharan 재현보다 낫거나, 더 엄격한 목표에서도 만족 | "격자 시뮬레이터 범위"로 주장 한정 |
| **4. 나머지 팔·ablation** | R0~R3, M−*, 실험 A/B (H1′, H2, H3) | 2~3주 | 설계 문서 기준 | 불필요한 요소 제거 |
| **5. 루프** | M+loop (검산 루프), R을 2→32로 (H4, H5) | 2주 | 모드가 많은 판에서 R을 늘리면 개선, 반복 수와 위반 모드 수의 상관 ≥ 0.5 | 루프 제거, 고정 깊이로 확정 |
| **6. 큰 판** | 10→30→50→100→150칸. 시간·개수·메모리 곡선 vs LS, GA, Manoharan (H6) | 1~2주 | LS·GA가 느려지거나 나빠지는 지점 이후에 우위 | "작은 판은 LS로 충분"이라는 경계선을 기여로 보고 |

총 약 10~13주. 2단계까지는 CPU(M4 Pro), 4단계부터는 GPU를 권장한다.

**논문 핵심 증거 3개**
1. 같은 몸통에 눈만 바꿔 끼운 표: 좌표 / 고정 주파수 Z / 모드 → 기술 간 결과
2. 판 크기별 시간·품질·메모리 곡선: LS, GA, Manoharan vs 우리
3. (루프가 살아남으면) 반복 수 vs 모드 수 그림

| C1 | **32점 검사의 가짜 성공** | `coarse_check.py`: 32점 검사가 최악 \|Z\|를 중앙값 1.2~3.8배, 최대 7배 과소평가. 행동의 53~90%가 1.2배 이상 과소평가됨 | 0단계(H0)를 먼저 통과하기 전에는 어떤 결과도 믿지 않는다 |

| C3 | **Manoharan과의 차이가 작게 보일 위험** | 그쪽도 Z 입력, 매 단계 갱신, 처음 보는 보드·라이브러리, 10~150포트, 다른 데이터셋 시연까지 함 | 차이를 숫자로 보여야 함: Manoharan 재현을 강한 기준선으로. 특히 GHz 공진이 지배하는 판(인터포저·칩)과 큰 판에서 |
| C4 | **"왜 LS를 안 쓰냐"** | `sanity_check`: LS가 10×10 판 8개를 3.2초에 풀고 greedy보다 훨씬 좋음 (31 → 3) | 6단계: 판 크기별 곡선으로 AI가 필요한 영역을 보인다. 기존 논문은 LS와 비교하지 않았다는 점을 오히려 강점으로 |

### 🟡 기술적 위험
| # | 걱정 | 대응 |
|---|---|---|
| T1 | 루프가 이득 없이 학습만 불안정하게 만듦 | 2단계는 루프 없이. 5단계에서만 시험. GRPO clipping, 앞쪽 반복은 기울기 없이 |
| T2 | 순수 루프는 반복 중 새 물리 정보가 없음 | 검산 루프 변형을 기본으로 (§2.2) |
| T3 | 모드가 매 수마다 생기고 사라져서 토큰 집합이 튐 | 집합 attention (추적 불필요), 위반 큰 top-K + 위반 중인 모드 전부 포함. 안정성 로그 |
| T4 | pole 추출 불안정 (M=8에서 붕괴, 정답 pole을 써도 top-1 regret 최대 18~25%) | K ≤ (M−2)/2 제한, AAA/VF 차수 규칙 고정, 실험 B에서 정확한 1단계 효과 특징 추가 |
| T5 | probe가 여럿일 때 모드 토큰 정의 | probe별 residue 벡터를 모드 특징으로, 주파수 2% 이내면 같은 모드로 합침 |
| T6 | f_ref 정의 | 대역의 기하 중심 f_c로 고정 (설계 문서 §3) |
| T7 | 긴 에피소드 (50~150수 + remove) → REINFORCE 분산이 큼 | 모방 비중을 크게, 그룹 기준선, 필요하면 critic |
| T8 | 선생님 품질과 비용 | greedy를 따라 하면 greedy의 편향을 배움 → LS 해를 선생님으로. 학습용 LS 해 생성 비용을 "빠르다" 주장에 포함해서 보고 |
| T9 | 작게 학습 → 크게 시험 실패 | 가장자리 셀 비율이 12칸 33%, 100칸 4%로 다름 (Yehudai 2021 경고). 학습 크기 분포를 넓히고, 크기별 곡선을 정직하게 보고 |
| T10 | 큰 판에서 LS도 빠를 수 있음 | 후보 평가 4.65 µs → LS도 빠를 수 있음. 실제로 재기 전에는 속도 이득을 주장하지 않음 |
| T11 | Z 데이터 자체가 필요 | 실제 칩 수천 포트의 EM 추출은 비쌈 (PAGA가 밝힌 한계). 범위를 "Z가 주어진 상황"으로 명확히. 단, 우리는 열 + 대각만 필요하다는 장점을 강조 |
