# 모달 토큰 트랜스포머 (Modal-Token Transformer, MoTT) 제안

작성 2026-10-19. 검증 스크립트: `research_notes/모달 토큰 검증/`

## 1. 한 줄 요약

정책의 토큰을 "격자 칸"이나 "포트"가 아니라 **PDN의 공진 모드(pole)** 로 바꾼다.
포트는 좌표 없이 "각 모드에 얼마나 참여하는지(residue)"로만 표현한다.
그러면 판 크기, 메쉬 해상도, 모양, 기술(PCB·패키지·인터포저·HBM)이 달라도 정책이 보는 입력은 같은 형태가 된다.

## 2. 관련 연구와 남은 빈자리

| 계열 | 대표 | 입력 표현 | 범용화 한계 |
|---|---|---|---|
| Park et al. (2203.15722) | Transformer + RL, HBM | 좌표 (x,y,z) + probe | 같은 PDN 안에서만. 다중 크기 학습은 future work |
| DevFormer (ICML 2023) | 격자 토큰 | 좌표 | 10×10 → 15×15 정도 |
| PhysEDA (2605.10547) | Manhattan 거리 감쇠 attention | 좌표 + 거리 편향 | 10×10 → 25×25 |
| Manoharan, TSIPI 2026 | 좌표 없는 transformer | Z 행렬 루프 인덕턴스(저주파 스칼라) | PCB 중심, 위치 순서는 greedy, 주파수 정보 없음 |
| Neural Modal Decomposition (NeurIPS 2026) | 모드 + 포트 결합 학습 | 포트 응답 | **대리모델(surrogate)**, 배치 정책 아님 |
| 고전 모달 배치 (US 6789241, Xu/Wang/Fan EMCSI 2020, HRMA) | 공진 피크 억제, 참여도 기반 배치 | 공동(cavity) 모델 | 학습 없음, 좌표 기반 |
| ML 일반 (Specformer, SignNet) | 고유값을 토큰으로 | 그래프 Laplacian | 배치·회로 문제 아님 |

선행조사 서브에이전트 결론: **"공진 모드를 토큰으로 쓰는 decap 배치 정책"과 "기술 간 범용화 주장"은 둘 다 찾지 못함.** 단, 부품들(모달 전개, 참여도, 고유값 토큰)은 각각 존재하므로 새로운 것은 "조합 + 학습 정책으로의 사용 + 범용화 증명"이다. (IEEE Xplore는 직접 수동 검색으로 한 번 더 확인 필요)

## 3. 핵심 물리 (왜 되는가)

어떤 선형 PDN이든 임피던스는 pole-residue 꼴로 쓸 수 있다.

Z_ab(s) = Σ_k [ r_k,ab / (s − p_k) + 켤레 ] + d_ab + s·e_ab

- p_k: 대역 안 공진 모드 (모든 포트 쌍이 **공유**)
- r_k,ab = φ_k(a)·φ_k(b): 모드 k에 대한 두 포트의 참여 곱
- d, e: 대역 밖 모드들의 합 = 잔여 저항·인덕턴스. **e가 바로 Manoharan이 쓴 루프 인덕턴스**

decap을 포트 i에 놓으면 probe 임피던스는 정확히
Z_pp' = Z_pp − Z_pi² / (Z_ii + z_d)
이므로, 결정에 필요한 정보는 (Z_pp, Z_pi, Z_ii, z_d) 뿐이고, 이 셋은 위 식으로 "공유 pole K개 + 포트별 residue + 잔여항"으로 압축된다.

따라서 **Manoharan의 표현은 이 분해의 잔여항(e) 부분집합**이고, 우리는 주파수별 공진 부분을 더한 완전한 분해를 쓴다.

부가 성질:
- residue는 φ의 **곱**이라 고유벡터 부호 모호성이 자동으로 사라짐. 축퇴 모드는 합이 사영행렬이 되어 기저 모호성도 사라짐 (SignNet/BasisNet이 따로 풀던 문제).
- probe가 모드의 마디선 위면 r_k,pp ≈ 0 → 그 모드는 probe에서 안 보이므로 위반도 안 일으킴. 비율(φ_i/φ_p) 대신 곱을 쓰면 발산 없음.

## 4. 아키텍처

토큰 세 종류 (모두 log 정규화: 주파수는 목표 대역, 임피던스는 Zt)
1. **모드 토큰** m_k (K개, 가변): log(f_k/f_ref), log Q_k, log(|Z_pp(f_k)|/Zt(f_k)), 현재 위반량, r_k,pp
2. **포트 토큰** u_i (N개): 자기 특징은 잔여항 (d_ii, e_ii, d_pi, e_pi)/Zt. 모드와의 관계는 **엣지 특징** (r_k,pi, r_k,ii)
3. **decap 토큰** c_t (T개): log(SRF/f_ref), ESL, ESR, C 정규화

층 구성 (L회 반복)
- 모드 self-attention: 모드끼리 상호작용 (K² — 작음)
- 포트 → 모드 cross-attention, logit 편향 = log|r_k,pi|, 엣지 특징 MLP: "어느 포트가 어느 모드를 누를 수 있나" 집계
- 모드 → 포트 broadcast: 포트가 "내가 누를 모드가 얼마나 위험한가"를 받음
- decap ↔ 모드 cross-attention, 편향 = −|log f_k − log SRF_t|: "어느 종류가 어느 모드 주파수에 맞나"
- **포트끼리 직접 attention 없음.** 포트 간 결합 Z_ij는 물리적으로 모드 + 잔여 인덕턴스로 매개되기 때문. → 복잡도 O(N·K), 기존 Park/DevFormer/Manoharan의 O(N²)보다 HBM 수천 포트에 유리

출력: (포트, 종류) 쌍 점수 = 쌍선형(u_i, c_t | 모드 문맥) + stop. 행동 규칙(add / remove / 교체 / stop)과 보상(−개수/N_ref − λ·위반)은 기존 `decap_loop` 그대로.

환경 쪽 변경: 매 단계 loaded Z_pp(f)에서 피크 → pole 추출, 이미 은행(ZBank)에 있는 열로 residue를 최소제곱 적합 (기저 2K+2개, 비용 미미). 측정·EM 솔버(PowerSI, HFSS)의 Z 파라미터에 vector fitting을 걸어도 같은 토큰이 나오므로 **도구·기술 무관**.

## 5. 수치 검증 (이 프로젝트 시뮬레이터, `research_notes/모달 토큰 검증/`)

| 검사 | 결과 | 의미 |
|---|---|---|
| T1 메쉬 불변성: 같은 8mm 판을 16×16 vs 32×32 셀 | 모드 3개, 주파수 0.71/9.34/18.5 vs 0.70/9.34/18.7 GHz, Q·피크·참여도 거의 일치 | 셀 4배여도 토큰 동일 |
| T2 참여도 vs 실제 고유벡터 (사각·L자, 축퇴 포함) | 상관 0.997 ~ 1.000 | 추출한 토큰이 진짜 모드 모양 |
| T3 모드 수 K vs 크기 | 셀 64 → 900 (14배)일 때 K 2 → 5~9 | 토큰 수는 셀 수가 아니라 전기적 크기에 비례 |
| T4 (실패 사례) 모드 주파수에서만 평가 | 행동 순위 Spearman 0.2~0.3 | decap이 새 반공진을 만듦 → 피크 값만으로는 부족 |
| T5 pole-residue (K pole + d + s·e) | 적합 오차 1~2%, 행동 순위 Spearman 0.92~0.985 | **이 표현이 결정에 필요한 정보를 거의 다 담음** |
| T5' 인터포저형 파라미터 (셀 200µm, 유전체 1µm, 고손실) | Spearman 0.91~0.99, top-1 regret 0~2.8% | 다른 기술에서도 성립 |

T4 → T5가 설계의 핵심 근거: 피크만 보는 순진한 모달 토큰은 안 되고, **공유 pole + residue + 잔여항** 분해여야 한다.
한계: top-1 regret이 20×20에서 최대 19% (비슷한 행동이 많아 미세 순위가 흔들림). 정책은 환경의 정확한 피드백도 받으므로 치명적이진 않지만, 행동별 정확 효과 특징을 같이 넣는 ablation 필요.

## 6. 검증할 가설 (실험 설계)

- H1 기술 간 zero-shot: PCB 파라미터로 학습 → 패키지/인터포저/HBM 파라미터에서 평가. 비교: 좌표 정책(Park식), 격자 GNN(`gnn_phys`), Manoharan식(잔여항 e만 사용 = 우리 모델에서 모드 토큰 제거한 ablation)
- H2 메쉬·크기 불변: 학습 8~12칸 → 15/20/30/50칸, 같은 판의 해상도 2배
- H3 decap 라이브러리 일반화: 학습 때 없던 종류(SRF 다른)로 평가
- H4 복잡도: 포트 수 대비 추론 시간 O(N·K) vs O(N²)
- 필수 기준선: **비학습 모달 휴리스틱** ("probe 위반이 가장 큰 모드의 |r_k,pi| 최대 포트 + SRF가 가장 가까운 종류") — 리뷰어가 반드시 요구. 이걸 못 이기면 학습의 의미 없음. 그 외 greedy+prune, LS, GA, PAGA

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| 낮은 Q·겹친 모드에서 피크 추출 불안정 | 피크 대신 vector fitting으로 pole 추출 |
| 고주파·큰 판에서 K가 커짐 | 위반 큰 순 top-K + 나머지는 잔여항으로 흡수 |
| 단계마다 모드가 이동, 대응 관계 끊김 | 모드는 집합(set)으로 다루므로 추적 불필요. 순서 무관 attention |
| 다중 probe | 모드 토큰을 probe별로 만들거나 r_k,pp 벡터를 모드 특징으로 |
| Neural Modal Decomposition과 겹침 지적 | 그쪽은 응답 예측 대리모델, 우리는 순차 배치 정책 + 매 단계 재추출 + decap 토큰 + 기술 간 범용화 |

## 8. 재검증 (2026-10-19, 같은 날 2차)

**노벨티 하향 조정.**
- Neural Modal Decomposition (Park & Sengupta, NeurIPS 2026, arXiv 2609.14402, 전문 읽음): 공유 pole K=32 + 포트별 결합계수 + cross-attention, 2포트 학습 → 3~5포트 zero-shot. **표현(공유 pole + 포트 residue) 자체는 이미 있음.** 단 대리모델(응답 예측)이고 RL·배치·decap·PDN 없음. 반드시 인용.
- Manoharan TSIPI 2026 (IBIS 2025 슬라이드로 대신 확인): 상태 = 샘플링된 Z(f) 행렬 + 목표 + decap 4특징, 매 단계 갱신, REINFORCE, 25~75포트 학습 → 150포트. pole/residue 없음. "Z(f)를 상태로 쓰는 경쟁자"에 해당.
- 그 외 2024~26 학습 기반 decap 중 모달 상태 사용: 찾지 못함. EPEPS 2026 프로그램에도 없음.
- 남은 새로움: 모달 표현을 **순차 결정(정책)의 상태로** 쓰는 것 + 매 단계 재추출 + 포트가 모드만 보는 구조 + 기술 간 범용화.
- 서브에이전트 추정: 이미 그대로 출판됐을 확률 10~15%, 리뷰어가 "점진적"이라 볼 확률 40~50% (주파수 샘플 기준선 대비 이득을 못 보이면).

**경쟁 표현과 직접 비교 (`research_notes/모달 토큰 검증/freq_rival.py`).** 같은 Woodbury 식을 고정 log 주파수 M개에서만 평가:

| 방식 | 행동 순위 Spearman (PCB·인터포저, 12·20칸, 8문제) |
|---|---|
| 고정 주파수 M=4 | −0.94 ~ 0.98 |
| 고정 주파수 M=8 (현재 decap_loop 특징 수) | −0.97 ~ 1.00 |
| 고정 주파수 M=32 | −0.29 ~ 1.00 |
| pole-residue (K = 1~5) | 0.91 ~ 0.99 |

고정 샘플은 날카로운 공진 피크가 샘플 사이로 빠지면 순위가 뒤집힘. M을 늘려도 단조롭게 좋아지지 않음. 이게 Manoharan·Park식 Z(f) 상태 대비 우리 주장의 실험적 근거. 주의: 이 비교는 "샘플 값에서 최대값" 평가이며, 학습된 망은 샘플 사이를 보간할 수도 있으므로 실제 정책 학습 비교가 필요.

## 9. Universal Transformer(1807.03819) 기준 탐색 (2026-10-19)

- UT: 같은 블록을 깊이 방향으로 반복 + 위치별 halting(ACT). 길이 외삽 개선 주장.
- 후속: Looped Transformers for Length Generalization (Fan et al., ICLR 2025), Looped Actor (Rusch et al., arXiv 2609.37432, RL 정책, 상태별 loop 수, Boxoban에서 loop 수가 남은 push 수와 비례), Learned Stochastic Stopping (Kuo et al., NeurIPS/ICML 2026: looped 외삽은 run 간 분산 큼, loop 수 무작위화로 완화).
- decap/PDN/CO-RL에 UT·looped 정책 적용: 검색에서 찾지 못함 (TSP 크기 일반화 연구는 있으나 weight-tied 깊이 반복 아님).
- 구분: 바깥 루프(decap 하나씩 놓기)는 모든 autoregressive 정책이 이미 함 → UT 아님. UT에 해당하는 것은 한 결정 안에서 인코더를 반복하는 **안쪽 깊이 루프**.
- 판단: 국소 격자 GNN에서는 판이 크면 깊이가 더 필요하므로 UT가 크기 일반화에 도움. 하지만 모달 토큰은 포트가 모드를 통해 한 번에 연결되므로 크기 때문에 깊이가 늘 필요 없음. UT의 몫은 크기가 아니라 **난이도**(위반 모드 수, 빡빡한 목표, decap이 만드는 새 반공진) 쪽.
- 가설 H5: 모달 토큰 + weight-tied port↔mode 블록 + 학습된 halting에서, 필요한 loop 수는 셀 수 N이 아니라 위반 모드 수 K와 비례한다 (Looped Actor의 Boxoban 그림과 같은 진단).
- 위치: 핵심 기여가 아니라 2단계 ablation 축. 학습 때 loop 수 무작위화 필수.

## 10. UT 전문을 읽고 낸 발전 아이디어 (2026-10-19)

UT에서 가져올 것: (a) 같은 블록 반복, (b) 매 반복마다 위치·시간 임베딩 P^t를 다시 더함, (c) 위치별 halting (bAbI에서 근거 사실이 1→2→3개일 때 평균 반복 2.3→3.1→3.8), (d) halting이 다단계 추론 과제(bAbI, LAMBADA)에서 이득, 번역에선 오히려 약간 손해.

**A (핵심). 계산기를 부르며 생각하는 루프 (Physics-Queried UT)**
- 한 번의 결정 안에서 반복 t마다: 망이 "임시 계획" S_t(decap 여러 개 초안)를 냄 → 고전 솔버가 rank-|S_t| Woodbury로 초안을 단 PDN의 정확한 Z_pp(f) 계산 → 그 PDN의 모달 토큰을 다시 추출해 P^t 대신 물리 임베딩 Φ^t로 주입 → 초안이 목표 만족 + 안정이면 halt → 첫 decap(또는 초안 전체) 확정.
- 해결하는 것: T4 실패(decap이 새 반공진을 만듦)를 초안 단계에서 직접 봄. greedy가 조합에서 실패하는 문제(PAGA 24 vs greedy 61)를 "세트 단위 초안"으로 다룸.
- 원래 이중 루프 제안의 올바른 버전: 안쪽 루프가 회로 풀이를 흉내 내지 않고 정확한 계산기를 부름 (Jacobi 발산 문제 없음).
- 비용: 초안 k ≤ 30이면 주파수당 k×k 풀이, 미미. 솔버 출력은 입력 특징일 뿐이라 미분 불필요.
- 선행: looped transformer + halting 연구 다수(2603.08391, 2606.18206, 2607.20519, 2606.29983), 그러나 매 반복 정확한 시뮬레이터 피드백을 넣는 구조는 검색에서 못 찾음. 가장 가까운 후보 Looped World Models(2606.18208, 학습된 모델 사용 추정, 미확인) 원문 확인 필요.
