# 최종 모델 설계: 모달 토큰 트랜스포머 (MoTT)와 판정 가능한 가설

작성 2026-10-19, 같은 날 최종 검증 반영. 근거: `reports/모달 토큰 트랜스포머 제안.md`, `research_notes/모달 토큰 검증/` (`fair_check.py`, `coarse_check.py`).

## ★ 최종 검증 요약 (이 절이 이전 서술보다 우선)

### 기존 연구가 해결하지 못한 것 (확인된 범위)
1. **판 종류를 넘는 일반화.** 학습 기반 decap 연구의 일반화는 모두 한 기술 안에서만 이루어졌다. Park(HBM 한 PDN 안), DevFormer·PhysEDA(격자 크기), Manoharan TSIPI 2026·Zhang 2021(PCB끼리).
2. **주파수를 보는 방식.** Park는 Z를 단계마다 보지 않는다. 상태는 고정 특징 + 직전 배치 임베딩이고, 임피던스는 마지막 보상 계산 때만 쓴다(본문 확인). Manoharan은 단계마다 Z를 갱신하지만 **고정된 주파수 점**에서 본다. 고정 점에서 보면 공진 피크가 점 사이로 빠진다(아래 숫자).
3. **모달 정보를 정책 상태로 쓴 학습 기반 decap 연구는 없다.** 모달·pole-residue·vector fitting을 RL 상태로 쓴 경우를 웹 검색 여러 차례에서 찾지 못했다. IEEE Xplore 직접 검색은 아직 하지 않았다.

### 새로운 점 (정정됨, 하나로 압축)
> **울림(모드) 정보를 학습된 decap 정책의 상태로 처음 쓰고, 그 덕분에 판 종류(칩~PCB)를 넘어 일반화한다.**

설계의 일부일 뿐 "새로운 점"이 아닌 것과 그 선례:

| 요소 | 선례 | 우리와의 차이 |
|---|---|---|
| 공유 pole + 포트 residue 표현 | Neural Modal Decomposition (Park & Sengupta, NeurIPS 2026 포스터, arXiv 2609.14402) | 그쪽은 대리모델, 우리는 결정 정책 |
| 놓을 때마다 피크 다시 찾기 | US 6789241 (Sun, 2004): 옮길 때마다 스윕을 다시 하고, SRF를 피크에 맞춤 | 그쪽은 규칙, 우리는 학습된 정책 |
| 단계마다 정확한 Z 갱신 | Manoharan TSIPI 2026 (Park는 해당 없음) | 고정 주파수 Z 대신 모드 |
| 초안 → 정확 평가 → 수정 (안쪽 루프) | 개선형 NCO (NeuRewriter, DACT) | 모드 재추출 + 적응적 멈춤. 기여가 아니라 ablation |
| 반복 + 멈춤 | Universal Transformer, Looped 계열 | 같음. 도구로만 사용 |

### 공정 비교 (`fair_check.py`): 두 방법 모두 같은 M개 주파수 데이터만 사용
pole은 같은 M개 점의 Z_pp에 AAA 유리근사를 적용해 얻었다. 판 8개(PCB·인터포저형, 12·20칸)의 행동 순위 Spearman:

| M | 고정 주파수 (Manoharan식) | 모달 (MoTT식) |
|---|---|---|
| 8 | −0.97 ~ 1.00 (중앙 0.70) | 0.54 ~ 0.98 (중앙 0.79) |
| 16 | −0.35 ~ 0.93 (중앙 −0.20) | 0.82 ~ 0.99 (중앙 0.97) |
| 32 | −0.02 ~ 1.00 (중앙 0.62) | 0.93 ~ 0.99 (중앙 0.98) |

- **결론**: M ≥ 16에서 모달이 순위 전체를 안정적으로 맞힌다. M = 8에서는 둘 다 약하다.
- **정직하게 적을 점 1**: top-1 regret은 섞여 있다. M=32 중앙값은 모달 0% vs 고정 0.4%, 최대값은 모달 25% vs 고정 13%. "최고 한 수"를 항상 더 잘 고른다고는 말할 수 없다. 순위 전체가 안정적이라는 것만 말할 수 있다.
- **정직하게 적을 점 2**: 이전의 −0.29~1.00 vs 0.91~0.99 비교는 모달만 700점을 봐서 불공정했다. 이 표로 대체한다.
- **설계에 반영할 점**: pole을 데이터보다 많이 쓰면 오히려 나빠진다. 촘촘한 피크에서 얻은 pole K=5개를 M=8개 점에 적합하면 ρ ≈ 0이 된다. 그래서 **pole은 같은 데이터에서 AAA/VF로 뽑고, K ≤ (M−2)/2로 제한**한다.

### 주관적 추정 (근거 아님)
- 독창성 5~6/10
- 이미 출판됐을 확률 10~15%, "점진적"으로 평가될 확률 40~50%
- H5는 아직 실험이 없다

### 남은 확인
- **Manoharan TSIPI 2026 전문** (IEEE Xplore 문서 11511858, 학교 계정): 가장 큰 위험
- IEEE Xplore 수동 검색
- Looped World Models 본문 (초록상으로는 겹치지 않음)

## 0. 먼저 고칠 것: 검사 주파수 (가장 중요)

`coarse_check.py` 결과: 현재 환경은 log 간격 32개 주파수에서만 목표를 검사한다. 촘촘한(700점) 검사와 비교하면 다음과 같다.

| 판 | 32점이 놓친 최악 \|Z\| (촘촘한/32점) | 1.2배 이상 과소평가된 행동 비율 |
|---|---|---|
| PCB 12×12 | 중앙값 2.0배, 최대 7.0배 | 90% |
| PCB 20×20 | 중앙값 3.8배, 최대 5.7배 | 71% |
| 인터포저형 12×12 | 중앙값 1.2배, 최대 2.0배 | 53% |
| 인터포저형 20×20 | 중앙값 1.3배, 최대 2.6배 | 67% |

→ **지금 코드의 "성공"은 가짜일 수 있다.** 어떤 가설을 판정하기 전에 고쳐야 한다.

- **학습용 검사(적응형 격자)**: 32점 + 현재 loaded 곡선의 피크 주파수(최대 16개 추가). 피크는 모달 모델로 예측하고, 그 주파수에서는 정확한 열(column)을 계산한다.
- **최종 평가**: 마지막 해마다 log 700점에서 정확히 다시 계산한다(배치한 열 k+1개 × 700번 풀이, 해당 해에 한 번만).
- **H0 (검사 신뢰성)**: 최종 해의 99% 이상에서 적응형 검사와 700점 검사의 최악 |Z| 차이가 5% 미만이어야 한다. 실패하면 다른 실험은 하지 않는다.

## 1. 문제 정의 (고정)

- 판: 단위 셀 RLGC 격자 + VRM 경로. 모양(rect/L/holes), keep-out, probe 1~3개
- decap 라이브러리 T종 (C, ESL, ESR)
- 목표: 모든 probe와 대역 안 모든 주파수에서 |Z_pp(f)| ≤ Zt(f)를 만족하면서 **decap 개수 최소**
- 행동: add(포트, 종류) / remove / 종류 교체 / stop (현재 `decap_loop` 규칙 유지)
- 보상: −개수/N_ref − λ·(실패 + 위반량), N_ref = greedy+prune 개수, λ는 라그랑주 방식으로 자동 조정

---

## 2. 단계마다 하는 일 (환경 쪽)

1. **판 준비** (한 번): 32개 주파수에서 sparse LU → diag(Z0), probe 열 (기존 ZBank). 700점 probe 스윕은 **최종 검증(H0)에만** 쓴다. 모델 입력에는 쓰지 않는다. 그래야 대조군 R4와 데이터 예산이 같다.
2. **pole 추출**: 적응형 격자(32점 + 피크 근처 추가점)의 loaded Z_pp에 AAA/vector fitting → 대역 안 pole p_k. **K ≤ min(16, (M−2)/2)**, 위반이 큰 순으로 고르고 위반 중인 모드는 모두 포함한다(`fair_check.py`의 B1 방식).
3. **residue 적합**: pole을 고정하고, 32점 데이터만으로 Z_pi, Z_ii를 Σ r_k/(s−p_k) + 켤레 + d + s·e에 최소제곱 적합한다.
   - 검증: 순위 상관 0.97~0.98, top-1 regret 0~12%
4. **정확한 상태 갱신**: Woodbury (기존 그대로)

모달 모델은 **관찰(입력)**용이고, 판정은 늘 **정확한 계산**으로 한다.

## 3. 모델 구조 (MoTT)

### 토큰 (모두 무차원, log)
기준값 f_c는 대역의 기하 중심 주파수, Zt_c = Zt(f_c).

| 토큰 | 개수 | 특징 |
|---|---|---|
| 모드 m_k | K ≤ 16 | log(f_k/f_c), log Q_k, probe마다 log(\|Z_pp(f_k)\|/Zt(f_k)), 위반 여부 |
| 포트 u_i | N | 잔여항 d_ii/Zt_c, 2πf_c·e_ii/Zt_c, d_pi, e_pi; 플래그(놓을 수 있음, probe, 전원); 이미 놓인 decap은 그 종류의 decap 토큰 임베딩을 더함 |
| 포트–모드 엣지 (i,k) | N·K | 결합도 g_ik = \|r_k,pi\|/√(\|r_k,pp\|·\|r_k,ii\|), log(\|r_k,ii\|/Zt_c), cos(arg r_k,pi) |
| decap c_t | T | log(SRF/f_c), log(2πf_c·ESL/Zt_c), log(ESR/Zt_c), log(1/(2πf_c·C·Zt_c)) |

- 결합도 g는 비율이 아니라 곱으로 만들기 때문에 probe가 마디선 위에 있어도 발산하지 않는다.
- residue가 φ의 곱이라서 부호·축퇴 모호성도 없다.

### 층 (L = 4, d = 128, heads = 8)
1. 모드 self-attention (K²)
2. 포트 → 모드 cross-attention. logit 편향 = MLP(엣지 특징)
3. 모드 → 포트 cross-attention. 같은 편향
4. decap ↔ 모드 cross-attention. 편향 = −\|log f_k − log SRF_t\|/τ (τ는 학습)
5. FFN + 잔차 + LayerNorm

**포트끼리 attention은 하지 않는다** → 복잡도 O(N·K).

### 출력
- 점수(i, t) = MLP([u_i, c_t, u_i ⊙ c_t])
- stop 점수 = MLP(모드 평균, 전체 위반량)
- 행동 규칙 마스크를 적용한 뒤 softmax

### 선택 모듈: 계산기 검산 루프 (H4, H5용)
- 블록 가중치를 공유하고 T번 반복한다. 학습 때 T ~ U{1..6}에서 무작위로 뽑는다 (외삽 안정화, Kuo 2026).
- 반복마다:
  1. 상위 m개 행동으로 초안을 만든다.
  2. 정확한 Woodbury로 초안을 단 곡선을 계산한다.
  3. 모드를 다시 추출하고 모드 토큰을 교체한다. 포트 상태는 이어서 쓴다.
- halting: 모드별 halting 확률. 모든 모드가 멈추거나 T_max에 도달하면 끝난다.

## 4. 비교 팔 (같은 환경, 학습법, 파라미터 수 ±10%)

| 팔 | 판을 보는 법 | 무엇을 대표하나 |
|---|---|---|
| R0 coord | 포트 = (x, y) 정규화 + probe 오프셋, 포트끼리 attention | Park / DevFormer |
| R1 dist | R0 + Manhattan 거리 감쇠 편향 | PhysEDA |
| R2 LapPE | 포트 = 그래프 Laplacian 고유벡터 상위 16개 (SignNet 처리) | 모양 기반 위치 임베딩 |
| R3 Z-sample | 포트 = 고정 32개 주파수의 (Z_pi, Z_ii)/Zt, 포트끼리 attention | Manoharan식 |
| **R4 freq-token** | **MoTT와 구조가 같고, 모드 토큰 대신 고정 32개 주파수 토큰** | **가장 깨끗한 대조군: "모드 vs 고정 주파수"만 다름** |
| M | MoTT | 제안 |
| M−res | 잔여항 d, e 제거 | 공진 부분만으로 충분한가 |
| M−mode | 모드 토큰 제거 (잔여항만) | Manoharan의 루프 인덕턴스와 비슷 |
| M−dtok | decap 토큰 대신 one-hot 종류 | 라이브러리 일반화 |
| M−reext | 맨판(bare board)의 모드만 쓰고 다시 추출하지 않음 | 재추출의 가치 |
| M+loop | 계산기 검산 루프 추가 | H4 |

추가 공통 변수: **행동별 정확한 1단계 효과 특징** (지금 `--feat phys`에 들어 있는 것).
- 실험 A: 모든 팔에서 끈다 → 순수하게 표현만 비교
- 실험 B: 모든 팔에서 켠다 → 실용 시스템 비교

**비학습 기준선**: greedy, greedy+prune, LS, 개수 최소화 GA, PAGA(공개 코드 연결), **모달 휴리스틱** ("위반이 가장 큰 모드의 g_ik가 최대인 포트 + SRF가 가장 가까운 종류"를 반복한 뒤 prune)

## 7. 가설과 판정 규칙 (사전 등록)

| 가설 | 비교 | 채택 기준 | 기각 시 결론 |
|---|---|---|---|
| H0 검사 신뢰성 | 적응형 vs 700점 | 99% 해에서 차이 < 5% | 환경부터 다시 |
| **H1 표현 (핵심)** | M vs R4 (실험 A), S2·S4·S5 | count 5% 이상 적음 + success가 R4보다 1%p 이상 낮지 않음, 3시드 모두 CI가 0을 넘음 | "모드 표현이 고정 주파수보다 낫다"는 주장 폐기 |
| H1′ 기존 표현 대비 | M vs R0, R1, R2, R3 | 위와 같은 기준 | 해당 표현 대비 우위 주장 안 함 |
| H2 구성요소 | M vs M−res, M−mode, M−dtok, M−reext | 각각 S5에서 유의하게 나빠짐 | 그 요소는 필요 없음 → 빼서 단순화 |
| H3 학습의 가치 | M (실험 B) vs 모달 휴리스틱, greedy+prune, LS, GA, PAGA (같은 시간) | 어려운 부분집합에서 시간–품질 Pareto 우위 | 기여 = 표현·분석. "AI가 더 잘 고른다"는 주장 안 함 |
| H4 검산 루프 (선례: NeuRewriter·DACT, 기여 아님) | M+loop vs M, 어려운 부분집합 | count 3% 이상 감소, CI > 0 | 루프 제거 |
| H5 적응적 계산 | M+loop의 반복 수 | 위반 모드 수와 Spearman ≥ 0.5, 칸 수 N과의 편상관은 유의하지 않음 | "복잡도만큼 생각한다" 주장 안 함 |
| H6 확장성 | 추론 시간 vs N (판 준비 제외, 10~50칸) | M의 지수 ≈ 1, R0·R3은 ≈ 2 | 확장성 주장 안 함 |

**결과별 주장 가능 범위**
- H0 + H1 통과 → "공진 모드로 보는 정책이 고정 주파수·좌표 기반보다 크기·메쉬·기술 변화에 강하다" (논문 핵심)
- H1 통과, H3 실패 → 위 주장 + "물리 휴리스틱을 넘지는 못한다"를 정직하게 보고
- H1 실패 → 1단계 분석 결과(고정 주파수 검사의 맹점 + 기준선 표)가 기여

---

## 8. 실행 순서와 계산량

1. H0: 적응형 검사 구현 + 검증 (1주)
2. 기준선 표: 모든 세트에서 비학습 방법 실행 (1주) → 1단계 결과
3. M과 R4만 먼저 학습 (실험 A, 3시드) → H1 조기 판정 (2주)
4. 나머지 팔, ablation, 실험 B → H1′, H2, H3 (2~3주)
5. M+loop → H4, H5, H6 (2주)

CPU(M4 Pro) 기준 iter당 2~3초 (d=64, 3층 설정). 팔 하나 × 시드 3개 × 2000 iter ≈ 4~5시간. 팔 12개면 약 60시간이다. 3번 단계까지는 CPU로 할 수 있고, 4~5번은 GPU를 권장한다.
